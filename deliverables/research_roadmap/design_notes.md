# 研究思路框架图 · 设计说明

> 课题：**面向移动 GUI 智能体评测的应用状态污染检测和恢复方法研究**
> 用途：**独立科研插图**，插入中期答辩 PPT 第 5 页「研究思路」内容区
> 画布：1920 × 720（≈2.67:1，适配 960×540pt 版面的内容区，可用区约 900×340pt）
> 图源：`build_figure.py` → `research_figure.svg` → `research_figure_*.png`

## 1. 定位：这是插图，不是幻灯片

第一版做成了"整页汇报式"（带页面标题、学校、答辩日期、页脚、阶段进度、成果清单），
不适合嵌入已有 PPT，已废弃重做。当前版本：

- **没有**页面标题 / 项目名称 / 学校 / 日期 / 页眉页脚 / 页码 / 图例式状态标签；
- **没有**已完成-待开展进度汇报、实验数值清单、预期成果与投稿计划；
- 只有研究逻辑本身：**问题 → 矛盾 → 方法闭环 → 验证目标**。

## 2. 抽象层级：保留的 5 个核心逻辑要素

| # | 要素 | 为什么必须在这张图里 | 图上位置 |
|---|---|---|---|
| 1 | **研究问题**：任务顺序执行 → 持久化状态残留 → 后继任务起始条件失真 | 回答"为什么研究" | 左侧，两个手机图示 |
| 2 | **核心矛盾**：恢复动作本身也是设备操作 → 执行错误 = 制造新的污染 | 回答"问题的难点在哪"，也是本课题区别于普通"检测"工作的根本所在 | 左侧橙色矛盾框 |

## 3. 构图方案

采用**左—中—右三段式框架图**，段与段之间用箭头串联，整体读作一条研究主线：

```
研究问题 ──任务轨迹──► ┌──────── 状态恢复闭环 ────────┐ ──恢复后的状态──► 验证目标
（现象示意 + 核心矛盾）  │   ① 推断 ──► ② 生成            │                  （成功率对齐）
                        │        ▲            │          │                  （ΔSR/CTCI/PASR）
                        │        └──反馈再检测─┘③ 执行    │
                        └───────────────────────────────┘
```

- **左段（x 40–440）**：两个手机图示讲清"污染"这件事（任务 A 改状态 → 状态残留 → 任务 B 起始条件失真）；
  其下橙色矛盾框把"恢复本身有风险"点破，并给出架构的直接推论"生成可自由，执行必受控"；
  最下方两条设计约束（只依据轨迹证据 / 结转由代码完成）说明推断模块为何这样设计。
- **中段（x 500–1410）**：浅色容器代表**方法整体**，内部三个模块排成**三角形循环**
  （① 推断 左上、② 生成 右上、③ 执行 下方），实线箭头 = 数据流（污染清单、恢复任务），
  灰色虚线 = 反馈回路（恢复轨迹再检测），使"闭环"由图形结构本身表达，而不是靠文字解释。
- **右段（x 1456–1888）**：验证目标用三根条形对比表达——独立执行 / 有前置污染 / 本方法恢复后，
  恢复后的条与基准条对齐并标 "≈"；下方给出评价口径 ΔSR / CTCI / PASR、对照条件与人工干预率。

### 视觉编码

| 元素 | 约定 |
|---|---|
| 深蓝 `#1a365d` | 标题、模块名、基准条 |

## 5. 需要你确认的两处表述

1. **"执行错误 = 制造新的污染"** 是把方法文件里的"恢复错了等于制造新的污染"改写为对称句式，
   若你更想沿用原句，可直接改 `build_figure.py` 里对应字符串。
2. **右段"本方法恢复后"的条形**：目前画成与"独立执行"等长（表示目标态），
   属于**目标而非结果**。如担心被误读为已达成，可在讲稿中说明该图表达的是验证口径；
   若希望完全避免歧义，可把该条改为虚线轮廓。

> 另：`docs/开题报告.md` 与 `design.md` v0.3 之间存在阶段 A 检出率口径差异
> （41 case / F1 0.980 vs 310 例 / F1 0.744），与本图无关（本图不含实验数值），
> 但关键成果页仍需统一，详见 `README.md` 备注。

## 6. 可编辑点

- `research_figure.svg` 含 3 个命名分组：`problem`（研究问题与核心矛盾）、`loop`（状态恢复闭环）、
  `goal`（验证目标）；另有 `research_figure_transparent.svg`（去底色版）。
- 文本为真实文本层、图形为矢量，导入 Figma / Illustrator / Inkscape 后可直接改字、改色、拆组。
- 全部坐标与文案集中在 `build_figure.py`；`icon_*` 函数是复用图元（手机、清单、环形箭头、栏杆），
  可换色或换形。改完重跑：

```powershell
mobile\Scripts\python.exe deliverables\research_roadmap\build_figure.py
powershell -ExecutionPolicy Bypass -File deliverables\research_roadmap\render_figure.ps1
```
