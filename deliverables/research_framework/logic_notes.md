# 作图前笔记

图是独立科研插图，不是幻灯片。口径取 2026-10-10 定稿：`experiments/state_recovery/docs/method.md` 与 `design.md` v0.3。不开题里的页面差分，不写实验数值。

## 1. 核心研究逻辑

连续评测在真实应用上按顺序执行。前序任务会在设备或服务器留下持久状态，后继任务的起始条件因此随顺序改变，测到的成功率不再只反映智能体能力。

既有清理是人工写好的指令，交给同一个 GUI 智能体执行：覆盖不全，执行后不核对，失败和成功在记录里无法区分。快照与重启也清不掉服务器侧残留。

难点不是“检测出变化”，而是恢复本身也是一次设备操作。恢复错了，就是新的污染。所以生成可以自由，执行必须受控；不确定或不可逆就挂起，不猜测。

方法是一条闭环，不是三张并列说明：

1. 推断。输入是任务描述和执行轨迹，不是 success 标志。模型只判断本任务造成的变更；没清掉的残留由代码结转，链断则不往下传。输出经模式校验和轨迹接地，不通过则停，不产出清单。清单为空就不恢复。
2. 生成。只为本任务需要处置的变更写恢复任务：目标可以自由写，但人名、设置名必须来自清单且有轨迹证据；分开写执行前检查和预期终态；不可逆操作只生成，不自动执行；前序结转项不重复生成。
3. 执行与验证。在设备上做逆操作。执行前若已经干净，则零动作。执行后由另一个模型对照预期终态，执行者不自评。不符合最多再试一次，仍不符合就挂起。恢复轨迹送回推断，检查有没有新副作用。

要验证的是性质，不是某一轮分数：恢复是否正确、重复执行是否幂等、是否引入新副作用、不确定与不可逆是否被挂起而不是被猜完。研究目标是让后继任务的起始状态不再依赖前序残留。

与开题的差别：开题把检测写成任务前后关键页面的语义差分。定稿的主路径是轨迹推断加代码结转，再加接地校验。本图跟定稿。41 例与 310 例两套检出率口径互不一致，图中不出现数字。

## 2. 需要保留的

只保留读懂研究逻辑所必需的五件事：

1. 问题如何逼出方法：顺序执行、持久残留、后继起始条件失真，以及既有清理为何不够。
2. 核心约束：错恢复即新污染，因此生成自由、执行受控、不确定则挂起。
3. 三个协作模块及其顺序、输入输出和约束。箭头是主结构，不是三张信息卡。
4. 执行、独立验证、一次纠正、失败挂起，以及恢复轨迹再推断这条反馈。
5. 收束到待验证性质和研究目标，不收束到结果图。

不放进图里的：课题名、学校、答辩日期、页眉页脚、页码、进度阶段、指标数值、对照实验表、预期论文和时间表、装饰性手机、状态图例。
