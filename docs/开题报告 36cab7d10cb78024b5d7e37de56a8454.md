# 开题报告

# 面向移动GUI智能体评测的应用状态污染检测和恢复方法研究

## **1. 课题的目的和意义**

### **研究背景**

随着大语言模型（LLM）与多模态大语言模型（MLLM）的快速发展，基于图形用户界面（GUI）的智能体（GUI Agent）已成为人机交互领域的前沿热点。GUI Agent 能够通过视觉感知屏幕内容并自主规划执行操作序列，在移动端任务自动化（如 AppAgent [9]、Mobile-Agent [8]）、桌面任务执行（如 OSWorld [2]、Windows Agent Arena [6]）、无障碍辅助（如 Guardian [23]、GPTVoiceTasker [24]）等场景展现出巨大潜力。展现出巨大潜力。为了评测这些智能体的定位、规划等能力，学术界和工业界提出了一系列在线评测基准（Online Benchmark），如 AndroidWorld [1]、OSWorld [2]、WebArena [3]、Android Agent Arena (A3) [4] 等，用于评估 GUI Agent 在真实交互环境中的任务执行能力。

为保障各评测任务相互独立，确保每项任务均从预设的标准干净环境启动、避免任务间相互干扰，现有主流基准数据集主要采用三类状态恢复方案：其一为虚拟机 / 模拟器全量快照回滚，典型代表包括 OSWorld [2] 基于 VirtualBox 的快照机制；其二是程序化环境重置，例如 AndroidWorld [1] 的初始化与清理脚本、WebArena [3] 的数据库重置、A3 [4] 基于工具集驱动的状态复原；其三为人工手动恢复，多见于 Mobile-Agent [8]、Mobile-Eval [8] 及 AppAgent [9] 的评测环节。

但上述三种方案存在共同短板：均需人工预先界定基准干净状态与状态恢复逻辑，不具备对应用内部状态的语义理解与动态调控能力，极易出现状态过度重置或重置不彻底的问题。具体来看，快照机制以整机系统为最小回滚单元，执行后会清空所有应用数据，相当于完全重置运行环境。程序化重置依赖开发者手动编写初始化与清理脚本，清理范围受限于开发者最初的设计，不可泛化。人工重置则将状态恢复工作交由操作人员完成，不仅效率低、成本高，还会因操作标准不统一，给评测结果引入难以量化的干扰因素。

更为关键的是，上述模式在每次执行完任务之后重置状态，将评测局限于单任务场景。而在实际应用中，智能体的操作往往是连贯的流程化行为，例如商品检索、条件筛选、加入购物车、调整数量直至提交订单，是多任务序列化任务流。而现有评测框架会在单个任务执行完毕后清空全部上下文，导致这类连续式工作流场景无法开展有效评测。

在实际的多任务评测过程中，智能体执行任务 A 后会在 app 中遗留一系列状态变化——例如购物车中增加了商品、搜索框中残留了关键词、筛选条件被修改、偏好设置被更改、草稿被新建等。这些由前置任务引入的 **"状态污染"（State Pollution）** 会改变后续任务的起始条件，导致评测不公平：同一个智能体执行同一个任务 B，在有前置任务 A 和无前置任务 A 的情况下，可能得到截然不同的成功率。在GUI智能体在线测评领域，至今尚未有工作对状态污染问题进行系统性定义、检测与恢复。

### **研究目的**

本课题聚焦于 GUI Agent 评测中的状态污染问题，旨在构建一套"检测-恢复"双阶段的自动化状态管理方法。具体而言：

1. 首次对 GUI Agent 评测中的状态污染现象进行**形式化定义与分类**，建立从数据污染、UI 状态污染、配置污染到导航污染的多维分类体系

2. 设计基于 VLM（视觉语言模型）的**语义级状态差分方法**，通过对比任务执行前后关键页面的结构化语义描述，自动识别哪些状态变化是任务后果、哪些是污染副作用

3. 探索 LLM 驱动的**自主恢复任务生成机制**，使智能体能够基于检测到的污染信息自主规划并执行恢复操作序列，将环境恢复至可接受的干净状态

### **学术意义**

在**理论层面**，本课题首次提出"GUI 状态污染"这一概念并将其纳入 GUI Agent 评测问题的研究视野，填补了当前该方向在跨任务状态管理方面的理论空白。

在**技术层面**，本课题创新的语义级状态差分方法突破了传统视觉差分（如感知哈希、SSIM）和结构差分（如 View Hierarchy diff）"能检测变化但不知变化含义"的根本局限，实现了从"是否变化"到"变化了什么语义"的认知跃升；基于 LLM 的自恢复任务生成机制则首次将 agent 的错误恢复能力从任务内扩展到任务间。

在**方法层面**，本课题提出的跨任务污染指数（Cross-Task Contamination Index）和污染感知成功率（Pollution-Aware Success Rate）等新指标，为 GUI Agent 评测提供了更公平、更全面的评估维度。

### **应用价值**

本研究的应用价值体现于以下三个层面：

**第一，GUI Agent 评测基础设施层面。** 本课题的方法可作为现有评测基准的"状态管理插件"：一方面为程序化 teardown 脚本提供自动化验证，另一方面可部分替代耗时的快照方案，降低大规模评测的算力和时间成本；更重要的是，本方法使多任务序列评测成为可能，填补了当前所有基准的空白。

**第二，Agent 训练层面。**状态污染检测可作为强化学习训练中的负 reward 信号或环境 reset 加速器，直接服务于 AndroidWorld-Generalization [5] 等 RL 训练框架。

**第三，Agent 产品化层面。** 状态差分与恢复能力可成为 GUI Agent 的"执行安全"模块，使其在执行用户任务后主动报告和清理副作用，增强用户信任。

## **2. 课题研究状况**

### **2.1 现有在线评测基准的状态管理策略**

当前 GUI Agent 评测基准按环境类型可分为三类：桌面端、Web 端和移动端。

- **桌面端**以 OSWorld [2] 为代表，包含 369 个跨 Ubuntu/Windows/macOS 的任务，运行在 VirtualBox 虚拟机中。每个任务从独立的 VM 快照开始，任务结束后全量回滚至基础快照。该方案恢复彻底但资源消耗大、速度慢。Windows Agent Arena [6] 与 WindowsWorld [7] 采用了类似的 VM 快照方案。WindowsWorld 的论文明确指出"当前基准主要关注独立单一应用任务"，承认了多应用工作流评测的缺失。
- **Web 端**以 WebArena [3] 为代表，包含 812 个任务覆盖电商、论坛、GitLab、CMS 等自建网站。由于环境完全可控，其通过 Docker 容器 + 数据库 seed 数据重置即可恢复初始状态。但该方法的适用性受限于自建环境，无法推广到真实在线第三方网站。
- **移动端**是最活跃的评测领域。AndroidWorld [1] 是当前最具代表性的移动端动态评测平台，包含 116 个任务覆盖 20 个 app。其每个任务配有独立的 init/success/teardown 三类程序化脚本，在 Android 模拟器上运行。值得关注的是，AndroidWorld 设计者意识到了任务间状态隔离的必要性，但其 teardown 脚本的清理彻底性从未经过系统验证——这为本课题的"teardown 审计"场景提供了直接切入点。Android Agent Arena (A3) [4] 是首个明确针对真实在线 app 的 benchmark，包含 100 个任务覆盖 20 个第三方在线 app。A3 提出了基于 MLLM 的 essential-state 渐进式验证方法，并在 toolkit 中包含了环境重置模块。然而，A3 对状态重置困境的解决方案是"选型规避"——在 benchmark 设计阶段人工筛选"支持可靠环境重置"的 app，直接排除了即时通讯等无法重置的类别。Mobile-Agent/Mobile-Eval [8] 和 AppAgent [9] 则在评估中依赖人工手动恢复，不可扩展且引入人为偏差。

总的来说，现有在线 benchmark 的状态恢复可归纳为三条路线：VM/模拟器快照、程序化环境重置、人工恢复。三者都假设单任务独立执行，没有考虑多任务序列场景下的状态污染问题。

### **2.2 现有状态恢复技术路线及其局限**

除 benchmark 本身采用的重置方案外，学术界还探索了多种 GUI 状态恢复技术路线，可归纳为以下四类：

（1）**Deep Link 跳转**（如Delm [10]、APE [11]、Stoat [12]）：利用 Android 深层链接机制，通过构造深度链接 URI 直接将 app 导航至指定页面，无需从首页逐步点击。然而，deep link 只能恢复导航状态（到达特定页面），无法恢复页面内的数据状态（如购物车内容、搜索历史、表单填写进度等）。

（2）**Record & Replay**（如RERAN [13]、Barista [14]）：通过录制用户的一次完整操作轨迹（含触摸坐标、时间戳、UI 元素标识），在后续运行时按录制序列逐帧回放，以期重现目标状态。这类方法记录的是交互操作而非状态本身——若初始条件不同，回放将产生完全不同的结果。

（3）**自动 Undo / 反向操作**（如GUITAR [16]）：分析 GUI 操作的前向语义，自动推导其逆向操作序列——例如将"点击按钮 A 进入页面 B"的反向操作推导为"按下返回键"，或将"输入文本 X"的反向操作推导为"清空输入框"。部分基于有限状态机（FSM）模型的方法（如 Stoat [12]、APE [11]）在此基础上维护 app 的状态转移图，可通过图搜索规划返回目标状态的最短路径。

（4）**ADB 生命周期重置**：通过 Android 调试桥（ADB）直接清除目标 app 的全部本地数据或强制终止进程，使 app 回到首次安装时的初始状态。

现有四类方案均聚焦于页面跳转或全局状态清空，无法实现保留有效状态、定向撤销单一操作引发的副作用这一核心需求。具体来看，Deep Link跳转与Record & Replay仅能复原导航链路，无法识别和恢复购物车、编辑草稿等页面内部数据状态；自动Undo / 反向操作受限于操作可逆性，不可逆行为（如订单提交、消息发送）无法通过反向操作回退；ADB 强制重置则会清空应用全部数据，无法在多任务序列评测中保留上下文。而本课题所针对的状态污染问题核心在于细粒度状态恢复：智能体需要精准定位每一处被修改的内容，包括搜索框输入、筛选项变更、购物车新增条目等，并支持单独回退对应字段，同时不干扰其余正常状态。

### **2.3 发展趋势与研究切入点**

综合以上分析，GUI Agent 评测领域的发展呈现以下趋势：

1. **从离线静态评测向在线动态评测演进**：环境和状态管理成为评测基础设施的核心挑战

2. **评测粒度从单任务成功率向过程验证细化**：如 A3 的 essential-state，但跨任务维度的状态管理仍在视野之外

3. **LLM/VLM 的能力增长**：使语义级状态理解和推理成为可能，为超越传统像素/结构级方法提供了技术基础

**本课题的研究切入点**正是上述趋势的交汇处：利用 LLM/VLM 的语义理解能力，填补 GUI Agent 评测中"跨任务状态污染检测与恢复"这一长期以来被忽略但至关重要的基础空白。与 A3 的"选型规避"策略形成互补——A3 通过限制 app 选择来避免重置难题，本研究则通过语义级检测和自恢复机制来正面解决这个问题。

## **3. 课题主要内容、基本思路与技术路线**

### **3.1 课题主要研究内容**

本课题的核心目标是构建面向 GUI Agent 的状态污染检测与自恢复方法体系，主要研究内容分为以下四个部分：

1. **状态污染的形式化定义与分类体系构建**

对 GUI Agent 执行任务后在 app 中遗留的状态变化进行系统分类，按三个维度建立分类体系

| 维度 | 类别 |
| --- | --- |
| 污染对象  | 数据污染 / UI 状态污染 / 配置污染 / 导航污染  |
| 可逆性  | 完全可逆 / 部分可逆 / 不可逆 |
| 影响范围 | 仅影响当前 app / 影响系统状态  |
1. **基于 VLM 的语义级状态差分检测方法**

设计"任务前后关键页面采集 → VLM 结构化语义状态描述生成 → 语义差分与污染判定"的三步检测流水线：

- 自动确定每个 app 的"关键页面"集合（首页及核心功能页面）
- 利用 VLM（如 GPT-4V、Gemini Pro Vision、Qwen-VL 等）将截图转化为包含 UI 元素状态、数据状态、导航状态的 JSON 结构化描述
- 通过 LLM 对任务前后两个状态描述进行逐字段比较，区分"任务合理后果"与"污染副作用"，并输出污染类型标签和严重度评分
1. **LLM 驱动的自恢复任务生成与执行**
- 基于检测模块输出的污染描述，利用 LLM 自动生成恢复任务的自然语言指令
- 将恢复任务交由同一 GUI agent 框架执行，执行后再次采集状态并与基线对比，验证恢复效果
- 对于被判定为不可逆的污染操作，标记为"需降级处理"并回退到快照或程序化方案
- 设计递归监控机制：若恢复任务执行后再次检测到残余污染，则迭代生成新的恢复任务
1. **实验验证与评测指标设计**
- 在 AndroidWorld 或其他基准上设计受控实验，验证污染对成功率的影响
- 在人为引入不完整重置的污染场景中，评估检测模块的精度和恢复模块的成功率
- 与基线方法（快照重置、pm clear、无恢复）系统对比

### **3.2 基本思路**

本研究的基本思路是模拟人类面对"被弄乱的环境"时的认知处理过程：**先感知环境发生了什么变化（检测），再判断哪些变化需要恢复（分类），接着规划恢复步骤（生成），最后动手恢复并检查是否恢复干净（执行与验证）。**

技术路线的核心原则包括：

- **语义驱动而非规则驱动**：不依赖 hand-crafted 的 teardown 规则或固定的状态匹配模板，而是利用 LLM/VLM 的语义理解和推理能力来驱动检测和恢复决策，使其能够泛化到未见过的 app 和任务。
- **分级处理策略**：可逆污染直接生成恢复任务解决；部分可逆污染尽力恢复主要污染，标记次要残余；不可逆污染标记为需快照降级。
- **以评测公平性为最终检验标准**：方法的优劣不仅看检测/恢复的内部指标，更看能否实际消除或减弱多任务序列评测中的不公平现象——即在使用本方法后，任务 B 在有前置任务 A 时的成功率是否更接近独立执行时的成功率。

### **3.3 详细技术路线**

**阶段一：状态污染实证与形式化**

- 选取 AndroidWorld 中具有因果依赖的 task pair，使用开源 GUI Agent 分别在两种条件下执行 30+ 次，统计成功率差异和轨迹长度差异，获取污染问题的实证证据
- 基于实证数据，完成状态污染的形式化定义和多维分类体系

**阶段二：语义级状态差分检测模块**

- 设计关键页面采集策略
- 实现 VLM 驱动的结构化状态描述生成
- 实现 LLM 驱动的语义差分器
- 在 20-30 个 task pair 上评估检测模块精度

**阶段三：自恢复任务生成与执行**

- 实现 LLM 恢复任务生成 prompt 模板和生成流水线
- 实现恢复任务执行、验证与递归监控框架
- 实现不可逆操作检测与降级策略
- 在 50+ 个污染场景上评估恢复模块性能

**阶段四：综合评测与分析**

- 开展全面消融实验
- 计算 CTCI 和 PASR 等新指标
- 在至少一个应用场景中演示方法效果
- 撰写研究论文和课题结题报告

### **3.4 难点分析**

**难点一：语义级状态差分的可靠性。** VLM 对 GUI 截图的理解能力虽持续提升但不可靠率为零——在 A3 的评估中，Gemini-2.5-pro 在 essential-state 级别的准确率为 89.5%，Fine-tuned 的 A3RM 达 96.6%。但在跨 app 泛化场景下，未经 fine-tune 的 VLM 能否稳定输出结构化状态描述并正确判定污染，是本方法的关键不确定性。**对策**：建立 VLM-as-judge 的一致性评估机制（多次调用取多数意见），并对关键字段采用程序化校验（如通过 content provider 读取数据库字段）作为交叉验证。

**难点二：恢复任务的可执行性。** 生成的恢复任务需要由同一 GUI Agent 执行，而当前即使是 top agent（如 T3A + Gemini-2.5-pro）在 A3 上的任务成功率也仅为 53%。若 agent 无法可靠执行恢复任务，则整个恢复策略失效。**对策**：恢复任务的复杂度天然低于原始任务；可选择执行可靠性更高的 agent 专门负责恢复操作。

**难点三：不可逆操作的边界处理。** 对于已提交的订单、已发送的消息等真正不可逆的操作，语义恢复无解，需要快照降级。**对策**：建立不可逆操作数据库，在检测阶段即标记不可逆污染，并计算"需快照降级的任务比例"作为方法的覆盖度指标。

### **3.5 创新点**

1. **研究视角创新**：首次将"状态污染"概念引入 GUI Agent 评测领域，将其定义为需要被系统性检测和恢复的研究问题，而非被忽略或回避的隐含假设。
2.  **技术方法创新**：提出语义级状态差分方法，突破传统视觉/结构差分的"可检测不可理解"局限；提出 LLM 驱动的自主恢复任务生成机制，将 agent 的恢复能力从任务内扩展到任务间。
3.  **评测指标创新**：提出跨任务污染指数（CTCI）和污染感知成功率（PASR）等新型评测指标，为 GUI Agent 评测的公平性提供可量化的评估维度。
4. **应用范式创新**：本方法可作为现有评测基准的"即插即用"状态管理模块，不要求修改基准架构或 agent 框架，具有较低的接入成本和较高的实用价值。

## **4. 课题研究进展计划及相应考核目标**

本课题的研究周期规划为一年，分为四个阶段实施：

### **第一阶段：基础调研与实证验证（第1-3个月）**

**主要工作：**

1. 完成系统性文献调研，细化技术方案，确定 VLM/LLM 模型选型和关键 prompt 设计方案

2. 选取 AndroidWorld 或 A3 中的候选 task pair，设计状态污染实证实验

3. 开展小规模污染实证实验，获取污染现象的定量证据

4. 完成状态污染的形式化定义与分类体系文档

**考核目标：**

- 完成详细的技术设计文档和文献综述报告
- 获得状态污染现象的实证数据
- 完成状态污染分类体系文档

### **第二阶段：检测模块开发与验证（第4-6个月）**

**主要工作：**

1. 实现关键页面自动采集模块

2. 完成 VLM 结构化状态描述生成的 prompt 设计与优化

3. 实现 LLM 语义差分器原型

4. 在 20-30 个 task pair 上评估检测精度，与人工标注 ground truth 对比

**考核目标：**

- 语义状态差分模块原型代码完成，在测试集上达到准确率 ≥ 85%
- 完成 20-30 个 task pair 的检测评估报告
- 获取一组人工标注 ground truth

### **第三阶段：恢复模块开发与集成（第7-9个月）**

**主要工作：**

1. 实现 LLM 恢复任务生成 prompt 模板和生成流水线

2. 实现恢复任务执行、验证与递归监控框架

3. 实现不可逆操作检测与降级策略

4. 在 50+ 个污染场景上评估恢复模块性能

**考核目标：**

- 恢复模块原型代码完成，在可逆污染场景下恢复成功率 ≥ 70%
- 不可逆操作检测准确率 ≥ 90%
- 完成恢复模块评估报告

### **第四阶段：综合评测、迭代优化与成果整理（第10-12个月）**

**主要工作：**

1. 开展全面消融实验，对比各模块贡献和不同基线方法

2. 计算 CTCI 和 PASR 等新指标，量化方法对评测公平性的改善

3. 在至少一个应用场景中演示端到端效果

4. 撰写研究论文和课题结题报告

**考核目标：**

- 完成全面的消融实验报告
- CTCI 在使用本方法后平均降低 ≥ 50%
- 完成至少一个场景的演示
- 提交 1 篇学术论文
- 提交课题结题报告

## **6. 课题已有基础**

- **计算资源方面：**课题组具备可用于 VLM 推理调用（API 方式）和模型 fine-tuning（如 A3RM 式的特定场景优化）的 GPU 计算资源，可支撑本课题所需的 LLM/VLM 推理和微调实验。
